# Trosky Full Audit & Strengthening — 2026-07-09

A five-dimension audit (features, correctness, security, UI/visuals, worker/data
pipeline) followed by a remediation pass. 99 files changed. Build green
(`pnpm build`, 4/4 tasks).

---

## Verdict before the pass

The platform was **more real than its docs suggested** — messaging, onboarding,
inquiries, the revenue-action pipeline, and the scrape→rates→recommendation flow
are all genuinely wired. The foundations (RBAC helpers, token system, queue
architecture) were sound. What it had: four critical defects, ~15
correctness/security bugs, a half-finished rebrand, and a design system adopted
by only 3 of 17 screens.

---

## Fixed in this pass

### Critical
| Defect | Fix |
|---|---|
| **Occupancy editor data corruption** — switching hotels kept the old grid; Save wrote hotel A's numbers into hotel B | Selector now navigates (`?hotelId=`), editor state keyed per hotel, NaN guard, unsaved-changes confirm, bulk save wrapped in a transaction (`occupancy-editor.tsx`, `occupancy/page.tsx`, `actions/occupancy.ts`) |
| **Cross-tenant message injection (IDOR)** — `sendMessage` trusted caller `hotelId`, never validated `threadId` ownership | Thread is now the source of truth: loaded, access-checked against `thread.hotelId`, security-event logged, body validated by `messageSchema` (`actions/messages.ts`) |
| **Committed JWT fallback secrets** — any deploy with `NODE_ENV≠production` verified tokens with a public constant | Fail-closed always: missing secret throws in every environment (build phase excepted). HS256 pinned at all 4 verify sites (`lib/jwt-secrets.ts`, `lib/auth.ts`, `middleware.ts`, `app/page.tsx`) |
| **`pnpm db:seed` wiped any database unconditionally** | Guard refuses `NODE_ENV=production` or non-local `DATABASE_URL` unless `SEED_FORCE=true` (`prisma/seed.ts`) |

### Correctness
- **UTC timezone sweep (16 sites)** — every "today" boundary was server-local
  `setHours(0,0,0,0)` against UTC-stored `@db.Date` columns (wrong day east of
  UTC). All web services/actions/pages, worker jobs, and shared `getDateRange`
  now use `startOfTodayUtc()` / `addUtcDays()` (new canonical helpers in
  `@hotel-pricing/shared`). Day-stepping loops de-DST'd.
- **Pace page**: inert hotel selector now navigates; unvalidated `?hotelId=`
  IDOR closed (must be in the caller's allowed set — same fix on `/occupancy`);
  comp average now weighted via `computeWeightedAvg` (was a plain mean that
  disagreed with the dashboard); deterministic latest-rate pick (`orderBy scrapedAt`).
- **Portfolio page**: multi-OTA rows no longer double-count "Avg Today Rate"
  (dedupe to freshest per hotel); parallel queries.
- **Dashboard**: 7-day cards always fetch a full week even when the graph range
  is shorter (`fetchEnd`); command-centre service errors no longer masquerade as
  auth failures; landing page no longer swallows `NEXT_REDIRECT` (logged-in
  users actually reach /dashboard now); greeting hydration mismatch fixed.
- **Rate calendar**: `isOpportunityAction` was inverted (flagged recommended
  *cuts* as opportunity) — now `recommended > current`; revenue-action mutations
  revalidate `/rate-calendar` too.
- `updateHotel` now schema-validated (`updateHotelSchema`, extended for
  nullable clears); `getDashboardData` validates date strings and caps range.

### Security (beyond the two criticals)
- Rate-limit keys use `x-real-ip` / last `x-forwarded-for` hop (first hop is
  client-spoofable) via new `lib/client-ip.ts`; `/api/auth/refresh` is now
  rate-limited (30/15min, NAT-friendly); login timing side-channel closed with a
  constant bcrypt pad; `/hotels/new` gained the missing server-side analyst
  guard; `/api/scrape` no longer leaks raw error internals.

### Data layer & worker
- **Migration `20260709120000_hot_path_indexes`** (SQL verified against
  Prisma's own generated DDL): `ReviewSnapshot(hotelId,scrapedAt)` +
  `(competitorId,scrapedAt)` (model had **zero** indexes on the dashboard's
  hottest read), `DailyRate` re-keyed hotel/competitor-leading (date-leading
  pair dropped), `Promotion(hotelId,startDate,endDate)`,
  `Message(threadId,createdAt)`. Run `pnpm db:migrate:deploy` to apply.
- **BullMQ**: `attempts: 3` + exponential backoff on all five queues (transient
  failures used to drop jobs permanently); orphaned repeatable-cron schedules
  pruned on boot when `*_CRON` env changes; graceful shutdown closes Queues.
- **Recommendation engine**: comp rates older than 7 days excluded from the
  anchor (stale data was treated as current); new ±20% per-recompute swing clamp
  vs the hotel's own rate (engine previously ignored it entirely — recs could
  whipsaw with comps and, with null min/max, were unbounded); hotel min/max
  still win. `||`→`??` fixes so occupancy 0% / target 0 aren't coerced.
- Stale compiled `seed.js`/`.d.ts` artifacts untracked + gitignored (they
  predated the RevenueAction feature); `RecommendationInput` type re-synced and
  now consumed by `computeRecommendation` so it can't drift again.

### Visuals & UX (the brief: .impeccable.md)
- **Brand tokens corrected** (`globals.css`): primary `#A60101` authority red
  (was `#D5171E` — also fixes a WCAG AA contrast failure on white), destructive
  `#780000`, warm ink `#424040` (was navy `#0E1523`), warm neutrals. **Dark
  mode re-hued from blue-black (hue 221) to warm black + red** — the one thing
  the brief forbade. Charts/tour/logo/login all follow tokens now.
- **Design-system adoption**: `TroskyPageHeader` on 14 screens (was 3);
  `formatCurrency` everywhere (no more `$2400` next to `$2,400`); semantic
  colors (destructive/emerald pair/amber events/violet promos/teal signals)
  replace scattered red-500/green-500/indigo/purple; new shared primitives
  `EmptyState`, `PageSkeleton`, `RouteErrorFallback`, `Textarea`.
- **17 new route boundaries** — `loading.tsx` (6) and `error.tsx` (11) for every
  route that lacked them; on-brand 404.
- **A11y**: ~50 label/control associations (inquiries, hotel settings, dialogs),
  aria-labels on every icon-only button, `role="alert"/"status"` on messages,
  landing motion wrapped in `MotionConfig reducedMotion="user"`.
- **Features unlocked**: top-bar Refresh actually works now (was dead — shell
  never passed props); multi-hotel clients get a hotel switcher (top bar +
  dashboard honors validated `?hotelId=`); analysts pick the hotel when starting
  a message thread; rate plans can be activated/deactivated; OTA listings
  visible in settings; "AI Assist" honestly renamed "Smart lead scoring";
  STLY figures relabeled (they use today's ADR — historical rates aren't
  tracked); dead `hotel-dashboard.tsx`/`hotel-selector.tsx` removed.

## Known remaining gaps (deliberate, documented)

1. **Hotel-local timezones**: all "today" math is now consistently UTC (matching
   storage), but `hotel.timezone` is still never used — a Honolulu hotel's "today"
   flips at UTC midnight, not local. Proper fix needs a per-hotel date library
   pass.
2. **Signals pipeline is mock-only** (2 hardcoded Atlanta signals; geocoding is a
   2-city table). The plumbing is real; sources aren't.
3. **Booking scraper is a stub** (returns mock); Expedia scraper is real but
   selector-brittle. Only 3 of 6 revenue-action types have live generators
   (matches docs).
4. **Scrape job is monolithic** (all hotels in one job — now retried, but not
   per-hotel resumable) and `ScrapeRun`/`ReviewSnapshot` have no retention job.
5. **No refresh-token rotation/revocation** (stolen refresh token lives 7 days);
   in-memory rate-limit fallback is per-instance without Redis.
6. **CLIENT role can create inquiries/proposals/RFPs** for their own hotels —
   ownership-safe and arguably intended ("clients triage leads"); tighten to
   analyst-only if that reading changes.
7. **User deletion** hits FK RESTRICT (PriceOverride/Message/InquiryProposal)
   — needs soft-delete before an admin "remove user" feature ships.
8. `next lint` was never configured (no ESLint config in apps/web); the build's
   type-check is the current gate.
9. Fonts load via a render-blocking Google `<link>`; `next/font` would need
   network at build time — decide per deploy target.
